# Good Dad Family Trip — 설계 규칙 & 도구 스택 (정본)

사용자 지시(2026-08-03)에서 도출. SKILL.md의 7조 원칙 상세 + 권장 도구 조합.

## 7조 원칙 (상세)

1. **호텔 후순위 결정** — 호텔 후보 10~20개와 관광지 후보를 지도에 올린 뒤, 총 이동시간이
   가장 작은 지역/호텔을 고른다. "바다 전망"은 동선 점수 다음 순위.
2. **아이 피로도 = 최우선 비용** — 연속 도보 ≤25분, 1회 이동 ≤45분, 하루 주요 방문지 2~3곳,
   오후 휴식 1회. 취학 전/저학년일수록 더 보수적으로.
3. **최종 총액 + 예산 상한** — 왕복 교통·숙박·현지교통·입장료·식비·간식·예비비 전부 합산,
   목표 예산의 85~90%까지만 계획에 사용(나머지는 업그레이드/비상 여유).
4. **아이 전원 만족** — 바다·체험·동물·전망·놀이공원·쇼핑·휴식 중 ≥3 포함, 어른 위주
   (시장·사찰·카페) 연속 배치 금지.
5. **우천·폭염 대체** — 야외 장소마다 30분 이내 실내 대안을 미리 짝지어 당일 교체 가능하게.
6. **가격·시간 조회시각 표기** — 확정가(공식 요금표) vs 추정가(온라인 예매·시세) 분리,
   예약 직전 재확인 항목 명시, 수치 날조 금지.
7. **출발지 기준 최적 교통** — 수서 출발이면 SRT 직행 기본, KTX는 역 이동비/시간 포함 비교안.
   어린이 운임(만 6~12세 50%) 반영.

## 권장 도구 스택 (핵심 8 + 조건부 백업)

한 컨텍스트에 도구를 과다 노출하면 선택 정확도가 떨어진다 → 핵심만 기본, 나머지는 조건부.

| 역할 | 이 repo에서의 구현 (현재 가용) | 향후 연결 후보(MCP/API) |
|---|---|---|
| 전체 판단·산출 | **good-dad-family-trip (이 스킬)** | — |
| 정적 동선 지도 | **scripts/route_map.py** (빨간 번호) | Mapbox Static / Google Static |
| 실제 공유 지도 | **google-mymaps-builder** (KML→마이맵) | — |
| 장소·주소 조사 | **WebSearch/WebFetch** | Kakao/NAVER Maps, Google Places |
| 문서 산출(DOCX) | **scripts/md_to_branded_docx.py** | — |
| 호텔 실가격 | WebSearch(야놀자/트립닷컴/booking) | Booking Demand, Expedia Rapid, Amadeus |
| 관광 운영정보 | WebSearch + 공식 사이트 | 한국관광공사 TourAPI, Visit Busan |
| 고속철도 | WebSearch + SRT 공식 예약화면 | KORAIL/TAGO 열차 API |
| 날씨·우천대안 | WebSearch | 기상청 단기예보 API |
| 후기·가족적합성 | WebSearch | Tripadvisor |

> 위 "향후 연결 후보"는 아직 이 환경에 MCP로 연결돼 있지 않다(정직). 연결되면 조건부 백업 계층으로
> 승격하되, 매 컨텍스트 상시 노출은 피한다([[token-diet-hygiene]] MCP 위생).

## 산출 계약 (이번 부산 1안이 레퍼런스)

- DOCX: 요약 → 7조 반영 설계 → 교통(SRT/KTX 비교표) → 숙소(지역 동선 비교표) → 동선 개요 +
  **빨간 번호 지도** → 일자별 표 → 우천/폭염 대체표 → 경비 상세표(+파이차트, 확정/추정 구분) →
  예약 우선순위 → 다음 단계(N안 + 컨펌 비교표).
- 지도: route_map.py 정적 PNG(문서 삽입) + google-mymaps-builder KML(현장 임포트).
- 컨펌: 사모님/배우자용 한 장짜리 비교표(총경비·이동량·아이 만족요소·실내비중·추천대상).
